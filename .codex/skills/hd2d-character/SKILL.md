# HD-2D Character

プロジェクト指定の主人公・味方・NPC・敵について、ドット絵素材と足元基準の移動契約を制作する。人数、人物像、動作、方向数、エンジンを固定しない。

## 入力と範囲

[references/character-contract.md](references/character-contract.md) の入力確認表を使い、既存プロジェクトから条件を取得する。制作に必要な条件が不足し、推定できなければ確認する。人物像の提案は依頼された場合だけ行う。テスト制作を任された場合は最小のテスト条件を明記して進める。

仕様だけの依頼では設計まで、素材だけの依頼では素材までとする。移動実装は依頼された環境に合わせる。マップ、戦闘、HP/MP、成長式を独自に制作しない。共通データは安定したキャラクターIDで参照する。

## 素材制作

1. マップのドット密度、縮尺、配色、照明・焦点条件と、人物の外見を確認する。未提供のマップとの視覚整合は未検証と記録する。
2. このリポジトリの [generate2dsprite](../generate2dsprite/SKILL.md) を読み、組み込み `image_gen` でオリジナル素材を生成する。ローカル参考画像は生成前に表示する。コード描画をキャラクター素材の代用にしない。
3. Python はプロジェクトルートの `.venv/bin/python` を使用する。処理スクリプトはこのスキルの隣の `generate2dsprite/scripts/` を参照する。実行ディレクトリを確認してパスを解決する。
4. 動作ごとの複数行グリッドを生成する。4方向歩行などの一貫した方向別移動シートは同一グリッドでよい。左右反転で非対称装備が崩れる場合は個別に生成する。
5. マゼンタ除去、分割、共有スケール、足元整列を行い、厳密QCと目視で輪郭・体格・接地点を確認する。複数の接地動作には受理した基準動作の共有スケールプロファイルを使う。大きな攻撃FXは別素材にする。
6. 下記「歩行の必須合格条件」に従い、静止コマの比較と方向別ループの両方を確認する。手前/奥の描画の重なりと陰影、腕の逆位相も確認する。左右の脚を入れ替えるために人物全体を反転し、向きや非対称装備を変えない。
7. キャラクター一覧、方向・フレーム順・再生時間・ループ・待機フレーム・足元原点を出力する。足元原点と当たり判定の位置を一致させる。

## 歩行の必須合格条件

歩行では、全方向で左右の脚が交互に前へ出ることを必須とする。側面は同じ脚を腰・膝・すね・靴まで追い、前後が入れ替わることを確認する。膝の曲げ方や靴の高さの変化だけでは合格にしない。生成後に方向別のループを確認し、不自然な足運びは納品前に修正する。この確認をユーザーに委ねない。

エージェント自身が指定された各方向のコマ比較とループ確認を実施し、方向ごとの結果を記録する。数値QCの合格だけでは歩行を合格としない。同じ脚が常に前に出る場合は再生成して再確認する。確認を実施できない場合は未検証と明記し、完成した歩行素材として納品しない。

## 移動と接続

実装時は [references/character-contract.md](references/character-contract.md) の移動・マップ・音声契約を読み、自由移動かグリッド移動かをプロジェクト指定に合わせる。

- 描画時間に依存しない移動を使う。自由移動では斜め入力を正規化し、速度と時間間隔が増えても壁を抜けない連続判定または小刻み判定を行う。
- 足元の小さな形状で衝突判定し、確定した移動距離で歩行・足音を更新する。壁に押し続けても歩行や足音を継続しない。
- 会話・メニュー・非アクティブ化・マップ遷移時に入力を解除し停止する。再配置は到着座標と向きを受け取り、以前の押下を持ち越さない。
- 地形・歩行領域・材質・遮蔽・照明・焦点・カメラはマップの契約に従う。足音は音声側IDを参照し、再生状態はキャラクターデータから分離する。
- 追従・巡回・経路探索は依頼されたときだけ追加する。閉塞・到達不能・遷移時の振る舞いを定義する。

## 検証と納品

素材、アニメーション、実行環境内移動の実施状況を分け、[references/character-contract.md](references/character-contract.md) のチェックリストで記録する。生成しただけの素材や未実施のゲーム内確認を合格扱いにしない。

マップ未提供で4方向自由移動の確認を依頼された場合、[assets/movement-check/](assets/movement-check/) を出力先にコピーして最小検証面として利用できる。これは地図素材や製品用エンジンではない。生成済みシートと `character.json` を接続し、矢印/WASD・停止・衝突・斜め速度・再配置を確認する。設定は下記の形式で用意し、セル寸法・原点・方向の行順・表示名を生成結果に合わせる。グリッド移動や他の方向数ではプロジェクトに適した検証面を使う。実際のマップへの組み込みは別途検証する。

```json
{"displayName":"検証対象", "sheet":"sprites/sheet-transparent.png", "cellSize":128, "footOrigin":[64,119], "directions":["down","left","right","up"], "frameDurationMs":140, "speed":160, "collision":{"halfWidth":9,"halfHeight":5}, "footsteps":{"distance":36,"audioId":"footstep.walk"}}
```

この検証面は各方向4列、待機は列0、歩行は列0〜3の順に再生する。速度の単位は検証面のpx/秒、足音はイベントのみ。`.venv/bin/python -m http.server <空きポート> --bind 127.0.0.1 --directory <出力先>` で配信する。

納品には素材・プレビュー、キャラクター一覧、アニメーション・移動・衝突・音声接続定義、プロンプト、QC、仮定と未検証事項を含める。

# 澪を継ぐ者 ― 流域盟約戦記（仮題）

版: 独立レビュー反映・第2修正 / 2026-10-17 / 日本語・PCブラウザ向け一人用SRPG

**高さと水路を読み、誰の暮らしへ水を渡すかを決める。** 測量官の小部隊が、水門都市の記録改竄と強制放流の真相を追う。戦場では水門の操作に攻撃の一手を使い、次のラウンドの進路を変える。物語では証拠だけでなく、それを公にできる制度と生活基盤をつくる。

これは実装前の推奨企画。記載した数値・時間・工数は検証対象の仮説。今回は企画とレビューまでであり、ゲームやアセットが完成した意味ではない。

## 1. 推奨理由と守る核

FFTの高低差、位置取り、職業を組み合わせる育成、個人と政治が衝突する物語を参照する。一方、人物・地名・陣営・衣装・台詞・音楽・地形は本企画用に新規設計する。固有職や用語・既存シナリオを移植しない。

| 比較案 | 期待する魅力 | 制作上の問題 | 判断 |
|---|---|---|---|
| 流域都市と水門の政治劇 | 高低差・目的地・政治争点を一つの題材で結べる | 高さと水深の読み分けが必要 | 推奨 |
| 浮遊島の領土争い | 垂直方向の壮観さ | 飛行・落下・カメラで試作範囲が拡大する | 今回は採らない |
| 王位継承の群像劇 | 導入が分かりやすい | 参照作品との差と固有の戦術が弱い | 主軸にしない |

核は「高所を取る」「目的地へ分進する」「一手を水門に使う」の優先順位。水門で敵を即死させる仕掛けではなく、到着順と守る位置を変える仕組みとする。水を連続流体として計算しない。

想定する遊び手は、編成と地形を考えたいが、長時間の育成稼ぎを必須にしたくない人。1戦10〜25分、本編12戦、初回6〜8時間を目標とする。目標内訳は戦闘3〜4時間、会話と記録閲覧1.5〜2時間、編成・リトライ1.5〜2時間。戦闘が各10分で終われば短くなる。会話を長くして時間だけ満たさず、短い試作で数値と文章量を取り直す。

## 2. 遊びの循環と規模

状況と当事者の主張を読む → 地形・目的・水位変化を偵察 → 出撃4人を編成 → 交互に部隊を動かす → 必須目標と任意救助の結果を見る → 拠点で訓練を再配分 → 次の事件へ進む。

本編は4章・各3戦。操作可能な主要人物6人、出撃最大4人、基本職6種。敵は通常4〜6人、増援は予告する。自由探索都市・無限稼ぎ・オンライン・全章分岐・ボイス収録・3Dカメラ回転・恒久死亡は対象外。会話と地図上の移動で章を繋ぐ。

失敗時は同じ戦闘の配置・装備画面から再挑戦。消耗品や通貨を失わず、難所で育成不足による恒久的な詰みを作らない。本筋は一本、救助や任意資料の成否は支援の内容と後日談へ返す。必須証拠は必須目標で確保する。

## 3. 戦闘仕様

### 3.1 盤面・手番・行動

| 項目 | 初期仕様 |
|---|---|
| 座標 | 正方グリッドの整数(x,y)、高さh=0〜2。見た目は固定等角投影。高さと水深は別データ |
| 占有 | 1セル1人。敵味方とも占有セルを通過・停止不可。戦闘不能者は退避して占有解除 |
| ラウンド | 未行動者を陣営ごとに1人選び、交互に起動。各人1ラウンド1回 |
| 先手 | 奇数ラウンドは味方、偶数は敵。片側が尽きたら他方の残りを順次起動 |
| 1起動 | 移動1回＋行動1回、順序自由。移動を分割不可。最後にN/E/S/Wの向きを確定 |

交互選択では未来の全行動順は確定しない。UIは「次に動く陣営」「両陣営の未行動者」「水門発効時刻」を表示し、存在しない確定タイムラインを見せない。

### 3.2 攻撃・向き・高さ・射線

適法な攻撃は必ず命中。初期版には会心、反撃、ランダムダメージ、属性相性を入れない。

`ダメージ = max(1, 攻撃力 - 防御力 + 背面補正 - 防御行動補正)`

- 背面補正は近接のみ+2。対象から攻撃者への座標差と対象の向きベクトルの内積が負なら背面、0は側面、正は正面。向きは座標軸に対応し、見た目の画面左右とは区別する。
- 防御は行動を消費し、次の本人の起動開始まで被ダメージ-2、重複しない。移動後にも選択可能。
- 近接は水平マンハッタン距離1、高さ差1以下。押し出し・落下・斜め近接は扱わない。
- 弩も水平マンハッタン距離 `abs(dx)+abs(dy)` を使い、2〜4。差分(3,3)は距離6で射程外、(2,2)は距離4。射手が対象より高ければ上限5。高所の威力上昇はなく、隣接対象は撃てない。
- 射線は地形と壁・大型オブジェクトで遮断。ユニット自体は遮らない。角をかすめる線も接するセルをすべて判定する。味方を対象に攻撃不可。
- 高台への接近経路は2本以上を原則とし、水門・必須資料・脱出地点を高台一か所に集めない。

実装時の射線契約: 各セルの地表高さをh、射手と対象の照準点をh+1とし、中心間を3次元線分として扱う。通過セル区間内で線分が地形の高さ以下になるか、そのセルの `blocksSight` オブジェクト上端以下になるなら遮断。地形と接する境界も遮断扱い。発射セルと対象セルの地表は除外する。角の通過セル列を返す決定的なsupercover処理と、プレビュー・AI・本計算を共用する。これは手製の簡易モデルで、水理・弾道の再現ではない。

### 3.3 水門

水路領域ごとに作者が指定したセル集合と `dry/shallow` を保持する。全セルの高さhは水門で変化しない。浅瀬は移動費が変わるだけで、攻撃力・防御・射線を変えない。

1. 操作盤に上下左右で隣接、高さ差1以下なら操作可能。1行動を消費。
2. 対象セルと「次ラウンド開始に乾地／浅瀬へ」を確定前に表示。
3. 操作時には予約だけし、次のラウンド開始、起動前に一斉適用。
4. 同じ盤は1ラウンド1回、予約中の上書き不可。反転は発効した後のラウンドから可能。
5. 初期試作は浅瀬→乾地の1回のみ。敵は操作しない。本編では再入水と敵操作を段階導入する。

水門でダメージ・押流し・即死・通行不能・建物破壊は発生させない。上にいるユニットの位置も変えない。将来も必須地点の到達経路を消す切替は作らない。災害そのものは戦闘の期限と地域の避難に反映し、演出で見せた大洪水を黙って「移動費だけ」と扱わない。操作できるのは局所的な安全水路であるとUIと台詞で区別する。

### 3.4 敵AI・戦闘不能・勝敗

試作AIは乱数なし。プレイヤーの合法行動より検討範囲を狭くし、必ず「移動(移動なしを含む)→攻撃、攻撃不可なら防御」とする。攻撃後移動は検討しない。攻撃候補があれば最大ダメージ、なければ守備目標への残り経路距離を最小化する。占有目標はそこに隣接する合法停止セルの最小距離で評価し、いずれも到達不能なら無限大とする。ただし起動者自身の占有は除外し、本人が守備目標上ならそこへの距離は0、移動なしも合法候補とする。同点は移動費、y、x、対象ID、行動IDの昇順、なお同点の起動者はユニットID昇順で固定する。MVPの敵IDは順に `enemy-melee-01`、`enemy-melee-02`、`enemy-bow-01`。

終了向きは、最寄りの生存味方に向く。距離同点は味方ID昇順、方向は差の絶対値が大きい軸、軸同点はxを選ぶ。相手がいなければ現在向きを維持する。味方IDはリセ `ally-lise`、ガラン `ally-garan`、ネイア `ally-neia`。攻撃不能かつ距離がすべて無限大なら移動せず防御する。射程や水位はプレイヤーと同じルールを使い、隠れた能力値を持たない。NPC護送は後続工程で追加する。

HP0はその戦闘から退避。本編では恒久死亡なし。主人公戦闘不能は敗北。その他の退避者は戦闘後に復帰し、負傷による恒久弱体や必須戦への出撃不能を設けない。

例外は本編B12の拘束対象だけで、HP0を「制圧済み」とし、占有を解除して非戦闘の保全対象へ移す。通常の敵の退避と異なり逃亡した意味にはしない。実際の拘束は勝利後に裁定所の命令を持つ首府警備隊が行う。HP0を死亡として見せる演出は使わず、この例外はMVPへ入れない。

行動解決は「効果・ダメージ → 退避と占有解除 → 主人公等の必須生存判定 → 目標達成判定」。期限は両陣営の起動終了後に判定する。移動だけでも脱出達成を判定し、勝利確定後は残りの行動やラウンド処理を進めない。

## 4. 育成と職業

本編では章進行で全員共通の基礎レベルを上げ、戦闘の撃破数・回復回数に経験値を与えない。必須戦のクリア報酬として訓練点を得る。任意救助に育成必須資源を置かず、弱敵残しを不要にする。

各人は主職1つ＋他職で習得した補助能力1つ。職業ごとに2〜3能力、武器1枠・装具1枠。装備は固定入手と章ごとの定額補給を基本とし、ランダムドロップや消耗耐久は採らない。拠点では訓練点を無料再配分し、職変更に通貨を要しない。主人公の測量技能は物語上の専門性であり、水門操作の独占権にはしない。

| 職 | 役割 | 代表能力案・制約 |
|---|---|---|
| 測量官 | 地形理解と近接支援 | 測線: 味方1人の次の通常攻撃+2。射程3・射線必要、1行動、1人につき戦闘2回、同効果重複不可 |
| 堤防衛士 | 狭路と仲間の防護 | 護衛: 隣接味方の次の被ダメージ-2、自分の次起動まで。通常防御とは重ねず大きい効果のみ |
| 水路斥候 | 水路と遠距離 | 浅瀬費用1、弩。近接された場合は撤退や味方の支援が必要 |
| 水工師 | 機動支援 | 渡り板: 射程1の味方の次の移動に限り浅瀬費用1、戦闘2回。通行不能地形は作らない |
| 施療士 | 限られた回復 | 手当: 隣接味方HP+6、戦闘2回。退避した者を戦場に戻さない |
| 記録官 | 敵の方針を読む | 読令: 1行動、敵1人の優先候補を次のその敵の起動終了まで表示、戦闘2回。基本射程・能力等は最初から全職に公開 |

これらは本編用の候補数値。強化は追加起動や無限回復ではなく、対象・位置取りの選択を増やす。第1章は測量官・衛士・斥候・施療士を順次導入、第2章で水工師と記録官を開く。特定職不在でも必須目標を達成可能にする。試作では技の横断継承・職変更を実装しない。

読令は未来の固定予言ではなく、誰かの移動・HP変化・向き・水位変更後に同じAI評価で再計算する「現在ならこの候補」という表示。次の敵起動前でも候補が変わったことを明示し、追加行動は消費しない。読令で守り方を変える局面、測線で自分の直接攻撃より目標達成に貢献する局面を各1件以上リプレイで示せることをP4の採用条件とする。成立しなければ数値・効果を修正またはその能力を差し替え、弱い能力を確定採用しない。

## 5. 世界と美術

舞台は七つの水門都市が結んだ**セヴラ流域盟約**。水議会は取水量、航路税、堤防維持費を決める。票は人口より「堤役口数＝維持費負担」に重く配分され、下流の開拓村や流民は負担と被害を受けても代表を持てない。

盟約には議会の政策決定から独立した**盟約裁定所**があり、違法拘束・公文書改竄の審理と証人保全を担う。存在は第1章の接収命令への異議で示す。水務卿は行政長で、議会票や裁定所への拒否権を自動的に持たない。

中央水務院は首府と大貯水池を守れば翌年の飢饉を防げると考える。下流共同会は繰り返し遊水地にされる暮らしを変えたい。運河商盟は航路と融資で生活を支える一方、一部は水害地取得で利益を得る。合理性を共有する人物と、隠蔽・拘束を選ぶ人物を陣営内で分ける。

時代感は測量器具、活版の公報、手動巻上げ水門が共存する架空の前工業社会。職能と装置で戦い、超自然の黒幕や魔物化で政治責任を消さない。

美術は**明るい石灰岩、青緑の水、錆びた銅の金具、朱の検測印、蝋引き布**。清潔な手描きHDの2Dで、影は大きな面、細かなノイズは抑える。騎士甲冑一辺倒ではなく、作業外套・脚絆・浮き袋・測量棒で職の輪郭を分ける。参照作品の衣装や肖像の描線を模倣しない。

高さ0/1/2は側面の帯とH表記、浅瀬は波線と水深表記で区別。陣営は縁の形・印章でも見分け、色だけに頼らない。音は鎖、滑車、水音、乾いた打楽器を中心とし、会話時の水音は抑える。楽曲と効果音の権利・出所は台帳に残す。

## 7. 開始から結末まで

### 第1章「消された水位」

雨期を前に、リセはトルネ渡し場へ取水杭の再検測に向かう。下流の住民は杭の撤去で権利が消えると抵抗し、中央の警備兵は名簿と水位痕を押収しようとする。実測と公図が食い違う。リセは地形変化と片付けるが、渡し守ネイアは以前から申告したと訴える。救護倉で住民名簿の接収命令を拒み、隊は公的補給を失う。これは自然災害と治安事件のように見えた問題が、行政の記録の問題へ変わる章。

### 第2章「署名のある罪」

下流の急進派も、上流集落を危険にさらす取水妨害を起こす。隊は共同会と条件付きで協力し、保守工イヴァと記録係ダニを迎える。文書蔵で二年前の「薄明放流」の指令とリセの再認証印が見つかる。彼女は締切を優先して下流村の実測を省き、古い高低図へ署名していた。ネイアは離脱する。商盟の航路を確保し、改竄に加担したトマを保護する代わりに、隊は航路維持の義務を負う。

### 第3章「水の代価」

リセは被害者の前で自分の署名を含む記録を開く。ネイアは赦しを約束せず復帰する。中央軍と下流急進派の間から住民を逃がす戦闘で、どちらの立場にも救うべき人がいると示す。トマの証言、保守記録、複数住民の避難時刻を突き合わせ、計画放流と事後の隠蔽を確定する。同時に貯水池には現実の危険があり、中央の危機認識すべてが嘘ではないと判明する。地方都市代表と証人を妨害から守り、公開審理を開くための票を集める。

### 第4章「誰の堤か」

首府市民も食糧難と増水に苦しむ。隊は外港を開いて救援船団を入れ、水務院の技師と補助弁を復旧する。ヴェスクの強硬派が予定の集中放流を強行しようとする。最終戦は都市の征服でなく、操作台を保持し避難と分散放流の時間をつくる戦い。ヴェスクを生存拘束し、技師の運用を継続したまま公開審理に渡す。

真相は「放流の必要性があったが、警告と避難時間を削り、被災村を無許可耕作地として処理し、補償と責任を逃れるため記録を変えた」。リセの署名は唯一の原因ではないが、危険を知らなかったという公的な口実に使われた。救助して帳消しにはしない。

### 終幕

水議会を倒して即日平等にはしない。地方都市の票、商盟の融資、共同会の保守作業復帰、首府への救援を条件に、期限付きの**流域再建協定**を結ぶ。

政治手続の仮仕様は下表。票は既存の都市代表が持ち、共同会や商盟がそのまま票を持つわけではない。全都市へ招集を告知し、欠席を口実に必要票を減らさない。

| 制度・局面 | 配分・要件と支持の根拠 |
|---|---|
| 既存12票 | 首府オルセ3、上流レダ2、商港ケスト2、中流ラウム2、東岸ベルカ1、西岸イェルン1、河口トルネ1。下流開拓村はトルネ都市領の外にあり投票権なし |
| 臨時招集 | 3都市の代表の連署で可能。B09でラウム・ベルカ・トルネが連署。支持票は計4で、この段階では協定可決に足りない |
| 可決 | 再建協定の予算・命令公開・暫定審議参加は既存12票の過半数7票が必要。恒久的な議席配分変更は別審議であり、結末では着手だけ |
| B10 | 融資・航路再開の条件を確認したケスト代表2票が支持し計6票。商盟は融資側の当事者で、代表の議決と区別する |
| B11〜終幕 | 救援と分散放流で首府の生活を守る見通しを得たオルセ代表3票が支持し計9票。上流2票とイェルン1票の反対は残る |

B11で首府代表の協力方針は得られるが、最終の正式採決は放流の安全確保後に行う。戦闘勝利から自動的に新政府が成立する構造にしない。

1. 水位と放流命令の公開、複数地域が立ち会う再測量。
2. 強制遊水地指定を受ける住民の避難・補償の権利。
3. 下流代表の暫定参加と議席制度改定の開始。
4. 航路収入と堤防予算を財源とする上限付きの再建基金。
5. 改竄と違法拘束の公開審理。技術職員を一括追放せず設備運用を続ける。

再建融資の返済、上流の負担、下流内部の土地争いは残る。リセは資格停止中の立会補助員として再測量へ同行する。最後の杭には、村代表・中央技師・下流の測り手が別々に同じ水位を記録する。ネイアは仕事として舟を出す。「赦す」という台詞を強制しない。

救助人物や任意の補償資料は短い後日談を変える。本筋の真相・協定・主人公の責任は固定する。

## 10. UI・入力

PCでマウスとキーボードの両方から完走できる設計。矢印/WASDはセル選択、Enterは確認、Escapeは取消、Tabは未行動者の巡回、Spaceは範囲比較。パンは端の操作またはドラッグ、ズームはボタンとホイールを用意する。画面外セルへも選択が追従する。

- 上辺: 目的、ラウンド期限、次に動く陣営、未行動者の小さな一覧。
- 中央: 戦場を主役とし、選択・移動・水位予告を必要時に表示。
- 右辺: 選択ユニットのHP・職・向き、攻撃プレビュー。通常は折り畳める。
- 下隅: 移動／行動／防御／終了の文脈コマンド。中央の足元は塞がない。
- 詳細: 敵射程、用語、人物関係、証拠は呼び出し式。長い会話中は盤面入力を止める。

移動先・対象を選ぶと、高さ、移動費、ダメージ、背面、射線遮断理由、水門対象と発効ラウンドが分かる。命中率は全攻撃100%なので率の装飾を増やさない。水位変更は模様＋テキスト＋セル縁で予告し、動きが苦手な利用者向けに非本質的な揺れを減らせる。

目標画面は1366×768。DOM部分は200%文字拡大でも主要操作が隠れないようスクロールと折畳みを用意する。狭い画面では詳細をドロワーにし、横長の戦場はパンで扱う。390×844のタッチではタップ選択→再タップ確定、大きさ44 CSS px以上の操作部品を予定。本編着手前のUI工程で対応し、MVPでのスマートフォン完走を約束しない。非表示のcanvasとDOMでフォーカスや入力を二重に消費しない。

## 11. アセットとローカルスキルの使い方

今回は画像生成を実行しない。次工程ではまず地形・足元・遮蔽が読める少数の実アセットを作り、量産前に見本戦闘で検品する。デバッグ用のグリッド表示はルール確認用に限り、生成絵の代わりの最終納品物にしない。

### マップ

`generate2dmap` の `grid_mode`、`layered_tilemap`、`interactive_scene_objects + scene_hooks`、グリッドメタデータを採用し、Phaserへ接続する。最初は独自JSONを使い、Tiled/LDtkを必須依存にしない。

地形セルは `x,y,height,terrain,moveCost,walkable,blocksSight`。オブジェクトは `id,cell,footprint,interactable,blocksMovement,blocksSight,height,assetKey`。水門は `regionCells,currentState,pendingState,effectiveRound` を持つ。盤面と射線の真実はJSON側で、生成絵の色や透過領域から推定しない。

地形タイル・水面・高台側面と、水門・柵・柱・人物・前景を分ける。水門・橋など大きな構造物は個別生成し、小物用の正方形パックに押し込まない。見本合成画像はQA用で、実行時の1枚絵マップにしない。高い飾りには `occlusionClass`、`actorSafeArea`、`occupantPolicy` を付け、占有中の人物・経路・選択セルが読めるかを見る。

### 人物・FX

`generate2dsprite` を優先し、clean_hd・3/4の同一視点・同一パレットを明示する。まず人物の受入原画、次に各方向の待機・歩行・攻撃・被弾。汎用スキルの生1行ストリップを採らず、一方向・一動作4フレームなら2×2、6フレームなら2×3で生成する。4方向歩行は規約の4×4例外も比較可能だが、まず検品しやすい方向別で試す。

生画像は#FF00FF、身体と武器を中央60〜70%に収め、足元固定・同じ立ち姿換算スケール。参照画像は生成直前に実際に表示して渡す。攻撃の大きな弧・飛翔体・命中FXは別シート。処理はプロジェクトの `.venv/bin/python` とローカルスクリプトを使い、共通scale-profile、alpha除去、決定的な切出し・組立だけを行う。フレームごとの拡大縮小で生成の不一致を隠さない。

足元・体格・武器・セル端の欠けを静止画とGIF、実画面の順で検品。身体スケール変動や足元ずれはローカルstrict QCの目安を使うが、数値だけで美術合格にしない。動画化の `video2dsprite` はGrok専用のため今回のCodex経路では不採用。

### 量の上限と出所

MVP: 地形セット1種、人物5外見(味方3＋敵近接共通＋敵弩)、水門前後2状態、記録表示、選択・範囲表示、攻撃/被弾FX各1、導入肖像3人分、環境音1と基本SE少数。本編: 味方6人、主要NPC4人の肖像、敵6外見、地形3系統を目安とする。職変更は全衣装差分ではなく装具とUIで識別し、アセット数の掛け算を抑える。

MVP人物の量産上限は以下。生成結果の再試行を含まない理論最小値であり、初めに味方1外見を作って実測する。

| 動作 | 1外見あたり方向×フレーム | 5外見の画像・生成単位 |
|---|---|---|
| 待機 | 4方向×静止1 | 計20フレーム。方向ごとに単体画像、20生成単位 |
| 歩行 | 4方向×4 | 計80フレーム。各方向2×2、20シート |
| 攻撃／射撃 | 4方向×4 | 計80フレーム。各方向2×2、20シート |
| 被弾 | 待機を流用 | 新規身体フレームなし。短い明度変化と別FX、縮小動作設定に対応 |
| 合計 | 36フレーム/外見 | 180身体フレーム、60生成単位＋QC。原画・肖像・FX・地形・再生成は別 |

最初の1外見の方向・歩行・攻撃が揃った時点で、P2の工数を再見積する。超過時は待機・被弾を上記のまま固定し、次に攻撃を4→2フレーム、敵の共通化を検討する。方向を減らす場合は背面の読み取りが悪化するためUI検証もやり直す。未検品の鏡像化で装具の左右を勝手に反転しない。

全生成物に `prompt-used.txt` またはmanifest内の手書きプロンプト、元画像、出所、利用条件、生成・修正日、方向・足元・寸法を残す。実行時は安定したassetKeyを使い、検品済み版だけ登録する。今回その画像や権利確認が済んでいるとは扱わない。

## 12. 技術選定と責務

**推奨は2D Phaser + TypeScript + Vite、DOM/CSSのHUD。** 既存本体がなく、Game Studioの標準とローカル2Dアセットスキルに一致する。ルール主体の小盤面を2Dで描くため、Three.jsや3D物理の導入理由は薄い。Godotはデスクトップや専用エディタを主対象に変える場合に再検討する。

[Phaser公式のVite TypeScriptテンプレート](https://github.com/phaserjs/template-vite-ts)が構成の参考になる。[Vite公式ガイド](https://vite.dev/guide/)にvanilla TypeScriptの導入経路がある。今回は依存を追加せず、メジャー版は選定保留。導入時にNode互換性、描画とアセット読込の最小確認を行って版を固定する。公式テンプレートの説明には版表記の揺れもあるため、そのまま最新版を無条件採用しない。

以下は将来の配置案であり、今回は作成しない。

```text
src/domain/       状態、移動、射線、戦闘、目的、水門、育成
src/ai/           決定的な候補評価
src/data/         戦闘と会話データの検証・読込
src/view/         Phaserの薄いScene、描画、アニメーション、投影
src/ui/           DOM HUD、会話、編成、入力マッピング
src/save/         JSON状態、版番号、コマンド履歴、復元検証
public/assets/    characters/environment/ui/fx/audio
tests/           ルール例、経路、リプレイ、後段のブラウザ検証
```

ルールは `reduce(state, command) -> {state, events}`。描画完了時刻やDate.nowを勝敗に使わない。状態にラウンド、次の陣営、未行動ID、HP、向き、水路予約、採取済みID、目標状態を含める。不正コマンドは状態を変えず理由を返す。AI・プレビューも同じ関数を使う。

表示の仮寸法は菱形タイル96×48、1高さ24px。`sx=(x-y)*48`, `sy=(x+y)*24-h*24` に原点とカメラ変換を加える。高さを無視した逆変換では誤選択するため、候補セルの投影ポリゴンを描画前後順と同じ規則で当たり判定する。重なりは地形・オブジェクト・人物を足元と高さで安定順序化し、高台や柱の背後を半透明化・輪郭表示する。この規則の正しさは最小描画検証で確かめる。

本編保存は描画オブジェクトを含まない版付きJSON。戦闘開始と結果を自動保存し、戦闘中断は行動確定境界のみ。localStorageの失敗時は通知し、JSON出力で退避できる設計を後段で追加。MVPはリトライと開発用の再生ログだけで、セーブUIは後回し。

## 13. 検証と合格条件

今回は静的な企画レビュー。以下は実装後に実施する試験であり、合格済みではない。

| 層 | 具体的な合格条件 |
|---|---|
| 決定論 | 同じ初期状態とコマンド列の100再生で状態とイベントが一致。アニメーション速度でも変わらない |
| 不正入力 | 占有・範囲外・高さ差2・行動済み・不正装置IDを拒否し状態不変 |
| 移動 | 高さ差1を通過、2は拒否。通常の浅瀬2セルは費用4、斥候は2。乾地迂回路が水門前後に残る |
| 攻撃 | 正面・側面・背面、防御、最小1、射程2/4/5、差分(3,3)の射程外と(2,2)の距離4、角の遮断で表示と実結果が一致 |
| 水門 | 操作直後は変わらず、予告した次ラウンドだけで発効。予約上書きを拒否。占有者は移動しない |
| 目的 | 記録1件では脱出勝利せず、2件で勝利。リセが先に脱出上、別の味方が最後の記録を採取した場合も勝利。敵全滅でも目的未達なら継続。8R最終行動の達成と期限切れを分ける |
| 勝敗 | 主人公退避・目標達成の競合は敗北優先。勝利後の敵起動や水門発効なし |
| 戦術 | 水門あり／なしの両方で敵AI込み8R以内の勝利ログを作る。単一の高台待機や防御連打だけでは最適にならない |
| UI | マウス・キーボードで起動から勝利/敗北/リトライを完走。移動先の高さと水位の発効を確定前に説明できる |
| 美術 | 高台・柱の背後、浅瀬の上、隣接セルで人物の足元・選択・行動が読める。攻撃で体格が縮まらない |
| 後段保存 | 中断復元がHP・向き・未行動者・水路予約・記録を維持。失敗を黙って成功表示しない |
| 本編ルール・物語 | 任意証拠を逃しても真相と協定が成立。離脱・加入・票・財源・保守を追える。B12の制圧フラグと連続保持、職業2種の直接攻撃より有効な局面を再現 |

初見協力者3人程度による形成的テストを予定し、水門の効果を操作前に説明できるか、最初の移動までに迷うか、失敗理由を説明できるかを観察する。標本が少ないため一般的な難易度保証にしない。プレイ時間・水門使用・再試行・誤選択を記録する際は開発用ローカルログを基本とする。

ブラウザはMacのChromeとSafariを最初の対象とし、起動・リサイズ・拡大・フォーカス・音声開始・縮小動作・WebGL再初期化を検査する。代表的な戦場・水門予告・高台遮蔽・結果画面のスクリーンショットを保存する。目標60fps、入力の目に見える応答100ms以内、MVP初回アセット転送10MB以内を暫定予算に置く。対象Macとブラウザ版を記録して測り、達成を先に断言しない。

## 15. 未解決・未検証と着手判断

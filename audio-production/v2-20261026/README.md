## 初回が同じに聞こえた原因と修正

初回ジェネレータは全曲4/4、同じ3音を同じ拍位置に反復し、4種類の和声と3種類の伴奏パターンをstyle番号で選択していた。旋律の輪郭も共通配列で、主に移調・テンポ・音色を変えていたため、ユーザーの「全部同じ」「冒険感がない」という指摘に対して構造から修正した。

`compositions.py` に16曲それぞれの専用A/B旋律、和声進行、拍子、フレーズ長、伴奏グリッド、低音、打楽器と編成を個別記述。共通の旋律配列やstyle%Nによる曲調選択を廃止した。river-recordの3音は準備/各戦の中間部で一度の短い引用だけ。タイトル/終幕の関連は冒頭2小節の引用に限定し、その後は別の歌へ進む。

## スキル・制作・編集原稿

指定 `.codex/skills/rpg-music/SKILL.md` と制作経路を再読。物語/地形は `src/domain/battles.ts`、`src/view/storyContent.ts`、`src/view/prologue.ts`。同梱のMIDI/レンダリング補助、FluidSynth 2.6.1、GeneralUser GS 2.0.3 BETAで全16曲を楽器レンダリングした。GM音源の音価/velocityによる表現で、専用奏法や映画的演奏品質は保証しない。SoundFont自体は配信していない。利用条件原文は `soundfont-license.txt`。私用/商用音楽制作の許諾と、作者の一部サンプル由来に関する留保を保持。

- `scores/`: 単曲JSON/MIDIと結果。`render/`: 3周期のJSON/MIDI。
- `masters/`: 44100 Hz、PCM16-bit stereo。
- `delivery/` と `public/audio/v2`: 22050 Hz、PCM16-bit stereo。
- `listen/`: 全16曲の最終配信PCM3周WAV、境界前後各3秒WAV。
- `short-previews/`: 現行タイトル/序章/B12の各20秒。原音源の単純切出し。
- `tactics-bgm-v2-three-previews.zip`: 同じファイル名で上書き。Libraryの同じ項目のversion 1へ置換成功。Library id `libfile_22d26fe585748191876f2bbd311396b0`、新File Service id `file_00000000282882469beb34d5dc62273d`。

## 同質性検査

`compare-compositions.py` と `composition-comparison-r2.json`。全16曲120組について、移調を除く音程差・テンポを除く拍位置差/音価のイベント列を比較した。主旋律と伴奏は同一イベント列なし、8要素連続列の共有なし。リズムの8要素列Jaccard最大0.18116。専用の拍子/和声/フレーズ表も保存。これは既存旋律の使い回し検出を助ける検査で、聴感上の違い、音楽性、楽しさの合格証明ではない。

## ループ・音量・技術検証

3周楽器レンダリングの中央周期を切出し、3周の文脈付きリサンプル後に中央周期を抽出。全区間ループで開始0、終端はmetadataのフレーム数exclusive。単なる末尾フェードではない。全16曲で最終PCMの境界jump/DC/20ms RMS差の診断フラグなし、上限到達なし。BGMpeak .32、既存の音量基準とheadroom .35を維持。true peak/LUFSは未測定。

`revision-r2-pcm.json` と `revision-r2-http.json`: 最終WAVを再デコード、全35件HTTP200/audio-wav/SHA一致。`browser-verification-r2.json`: IAB上で全35件をWebAudio再デコードしSource開始、BGM16曲loop=trueを観測。各音源の技術再生は冒頭約0.35秒のみ。`tests-r2.log`: 音声/演出/物語導線63テスト合格。`typecheck-r2.log`: 合格。`build-validation-r2.log`: 本体ビルド合格、既存の大きいJS chunk警告あり。初回の全1592テストは前改訂の記録で、今回の全件再実行とは扱わない。

**実聴取、各曲全尺、3周の自然さ、BGMとSE重ね合わせの聴感は未検証。生成やSource開始を「聴いた」としない。**

## 同じURLの上書きと保全

`publish-bgm.py` は選択BGMだけを同じ配信パスへ上書きし、19SEのSHA不変を検査。`se-preservation-r2.json` に記録。`public/audio/v2/manifest.json` に現行ハッシュ、`src/audio-versions.json` にBGMの内容ハッシュを保存。アプリは同じパスのハッシュ付きクエリを使用し、fetchをno-storeへ。`audio-v2-r2`で旧AudioBufferの使い残しを防ぐ。生成側も譜面内容のfingerprintと配信SHAが一致した場合だけキャッシュを再利用する。
